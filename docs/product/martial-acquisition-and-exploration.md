# 武學取得與探索設計

本文件擁有機緣、尋訪、pity、取得來源、acquisition provenance 與探索玩法。Fragment count、傳承完整度、修煉進度與境界由 [`martial-progression.md`](martial-progression.md) 負責。

除「提案」「未定」與「延期」內容外，其餘規則為已確認。

## 1. 取得語義

武學取得層使用「江湖機緣／尋訪」語義，而不是明顯的抽卡／開包語義。

- 機緣：自然遇到隨機傳承。
- 尋訪：主動追尋某一門武學。

機緣是否直接由每次 Task 完成觸發尚未定案，因為固定按 task count 觸發容易鼓勵拆任務 farming。

## 2. 一般隨機取得

兩層抽取是目前提案：

```text
先決定稀有度
→ 再從該稀有度可取得武學中選一門
```

原則：

- 同稀有度 V1 可等權。
- 某稀有度沒有可抽武學時，移除該 tier 並重新正規化其他 tier。
- 曾討論的 40/30/20/10、35/30/22/13 等比例都只是示例，不是定案。

## 3. 主動尋訪

同一時間只允許一門 active pursuit。

可以：

- 切換。
- 暫停。
- 為每門武學保留自己的尋訪進度。

切換後：

- 原目標進度不轉移。
- 原目標進度不消失。

普通機緣偶然取得該武學殘章時，不應懲罰性清空已累積尋訪進度；只有該武學傳承完整時才清除。

## 4. 保底與隨機原則

核心原則：

> **運氣可以讓使用者提早取得內容，但不應決定核心收藏是否永遠無法完成。**

偏好提案：

- 線索越多，提前取得機率逐步提高。
- 線索完整後直接取得／找到下落。
- 可搭配 soft pity / hard pity。
- 不使用固定額外 +5% 等會讓高稀有內容取得相對收益過大的簡單方案。

精確公式尚未定案。

必須等以下資訊較明確後再平衡：

- 機緣觸發頻率。
- 武學總數。
- 稀有度分布。
- 預期遊玩週期。
- 每日平均取得機會。

## 5. 多來源取得

同一門武學可以有多種取得途徑，但不同途徑應具有不同 gameplay identity。

| 來源 | 核心玩法 | 隨機性定位 |
|---|---|---|
| 尋訪／奇遇 | 探索未知內容 | 入口與結果可有較高 RNG |
| 線索追尋 | 長期累積後確定取得 | 集滿後固定 |
| 高人／師父傳授 | 關係／資格／條件 | 遭遇可隨機，達成條件後固定 |
| 石碑／山洞／遺跡 | 探索＋參悟 | 發現可隨機，解鎖通常固定 |
| 解謎／文試 | 特殊事件 | 事件可隨機，成功後固定 |
| 觀摩／自行領悟 | 觀察／理解 | 遭遇可隨機，結果可固定 |
| 藏經閣／書院 | 資格／進度 | 固定、可預期 |
| 交易 | 資源決策 | 出現可變動，支付後固定取得 |

不需要為武學取得先建立戰鬥系統。

## 6. Availability、Ownership 與 Provenance

以下概念必須分離：

- 世界中某武學是否仍可出現。
- 使用者是否已解鎖該武學。
- 使用者從哪個來源習得。
- 是否具有某個師承／門派的正式傳承語義。
- 使用者目前修煉進度。

玩家學會某門武學，不代表該武學從世界中消失。

「傳承完整後移出正常殘章池」只代表該取得池去重，不代表相關 NPC、事件或世界內容失效。

當 Progression 回報某武學傳承完整時，Acquisition 負責：

- 從正常殘章取得池移除該武學。
- 清除該武學的 active pursuit／尋訪進度。
- 保留已發生的 acquisition provenance。

最小概念應能區分 martial progress 與 acquisition / provenance；是否在 V1 使用獨立資料表仍待 Schema 設計。

## 7. Event 能力需求（提案）

若未來大量增加江湖內容，產品需要少量可組合的 Event／Requirement／Choice／Reward 能力，不應讓每種敘事形成完全不同的操作規則。

產品語義至少需要表達：

- 事件內容與類型。
- 觸發／參與條件。
- 可選行動。
- 結果與 Reward。
- 隨機入口與固定結果必須能分開表達。

具體 enum、Schema、Service 或共用 event engine 尚未定；只有在 Schema 工作取得確認後，才由 architecture 文件定義，不能從本節直接產生程式識別字。

## 8. 江湖地點與探索

江湖地點只有在產生真實策略差異時才值得建立。

若地點只是不同掉落率表，容易形成單一最佳解。

V1 若加入區域，優先使用：

- 區域卡片。
- 背景圖／文字。
- 尋訪入口。
- 已發現 NPC／地點的輕量重訪。

目前不需要：

- `currentLocation`。
- 移動時間／成本。
- NPC 移動。
- 完整大地圖。

探索負責「發現未知內容」；已知 NPC、地點與可重複互動適合固定入口。

## 9. 師承與門派

V1 可以保留拜師／師承 fantasy，但不建立完整門派 membership 狀態機。

可以存在：

- 記名弟子。
- 私下傳藝。
- 外門傳授。
- 江湖師承。
- 高人收徒。

目前不需要：

- `currentSectId`。
- 忠誠度。
- 門派政治。
- 退派／轉派。
- 冷卻狀態機。

主要收藏目標中的武學應存在不會永久錯過的取得路徑。

## 10. 延期／未定問題

- 機緣觸發規則。
- 武學總數與稀有度分布。
- 尋訪 soft pity / hard pity 的精確公式。
- 區域是否進入 V1。
- Event／Requirement／Reward 是否需要共用技術模型及其最終 Schema。
- acquisition provenance 是否在 V1 落成獨立資料表。
