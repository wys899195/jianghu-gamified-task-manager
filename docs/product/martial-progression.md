# 武學養成設計

本文件擁有武學傳承完整度、修煉進度、境界、修為池與主修分配。武學如何被發現、追尋及記錄取得來源，由 [`martial-acquisition-and-exploration.md`](martial-acquisition-and-exploration.md) 負責。

除「提案」與「未定問題」外，其餘規則為已確認。

## 1. 核心循環

武學系統的核心幻想：

```text
得傳承
→ 修煉
→ 突破
→ 大成
```

武學的主要作用是：

- 收藏。
- 長期成就。
- 個人修行史。
- 對現實任務提供短而有感的 meta-progression。

武學不直接宣稱等同使用者的真實能力。

## 2. 稀有度與分類

稀有度描述「傳承有多難遇」，不代表戰力強弱。

稀有度四級名稱屬提案：

- 流傳甚廣。
- 少有流傳。
- 江湖罕見。
- 近乎失傳。

高稀有度不應功能性更強，避免低稀有武學失去收藏價值。

武學可有橫向門類，例如拳掌、劍法、刀法、身法、內功、指法、槍棍、奇門。

分類主要服務資料整理、圖鑑與世界觀；V1 不因不同分類建立多套獨立 progression 或戰鬥系統。

## 3. 傳承完整度與修煉進度

「殘章／傳承完整度」與「實際修煉進度」分離。

- 殘章決定目前可修煉上限。
- 武學修為決定實際境界。
- 未取得必要傳承時，即使修為很多，也不能超過目前上限。

## 4. 殘章

V1 方向使用「取得下一缺卷」，不抽特定卷。

```text
抽到某武學
→ 增加該武學下一個缺少的殘章
```

後端可只保存 `fragmentCount` / `scrollCount` 類進度。

殘章不是一般背包 stackable item。

當某武學傳承完整後：

- 不建立重複殘章 → 粉塵／拆解之類 economy。
- Progression 對外提供「傳承已完整」的狀態；取得池與尋訪如何反應，由 Acquisition Domain 定義。

## 5. 境界

境界數量、名稱與成本尚未正式定案，以下為提案：

曾討論候選：

- 初窺門徑。
- 略有小成。
- 登堂入室。
- 融會貫通。
- 爐火純青。
- 神功大成。

境界規則應在武學升級 UI 與 Schema 落地前確認。

## 6. 武學修為

武學修為是唯一武學升級資源，不是一般貨幣。

不能用於：

- 購買武學。
- 購買殘章。
- 一般物品。
- 尋訪次數。
- 其他服務。

已確認依賴方向：

```text
真實 Task 推進／完成
→ 武學修為
→ 武學修煉
```

避免重新建立：

```text
Task
→ 閱歷
→ 尋訪
→ 修為
```

等較長的 economy chain。

修為池可以長期累積；目前不因為修為來自真實任務就額外建立每日 cap、疲勞或冷卻。

## 7. 主修武學

V1 主修規則屬提案，偏好同時只有一門主修。

主修決定「之後新得到的修為」如何流向，不會自動消耗既有修為池。

規則：

- 無主修：新修為全部進入修為池。
- 有主修：新修為優先投入主修。
- 主修達到目前上限／已大成：overflow 回到修為池。
- 新取得殘章提高上限時，不自動消耗既有修為池。
- 修為池由使用者手動決定如何分配。

未來可以把「主修」與「武學配置」分開，但 V1 不建立外功／心法／輕功各一套獨立分配系統。

## 8. Domain Guardrails

- 武學靜態定義與使用者武學進度必須概念分離。
- 不因未來可能存在秘籍或物品，就提前建立通用 Item / Inventory Domain。
- Task 系統擁有 Reward 計算；本文件只負責收到修為後的 allocation、overflow 與 progression。
- 武學不得反向要求特定 Task 的最高層產品原則只由 [`product-principles.md`](product-principles.md) 定義。

## 9. 未定問題

- 所有武學是否使用相同殘章數；V1 提案為統一卷數。
- 最終殘章卷數。
- 境界的最終數量、名稱與成本。
- V1 是否正式採用同時一門主修，以及主修切換規則。
